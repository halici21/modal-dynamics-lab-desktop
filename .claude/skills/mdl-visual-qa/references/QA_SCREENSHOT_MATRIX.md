# QA screenshot matrix — naming and state reference

## Existing naming convention (source: tests/visual/)

The project already names visual-regression baselines as `<release>-<workspace>-<state>.png`, for example:

- `full-r2-sdof-dark.png`, `full-r2-sdof-light.png`, `full-r2-sdof-narrow.png`, `full-r2-sdof-reduced.png`, `full-r2-sdof-energy.png`, `full-r2-sdof-phase.png`, `full-r2-sdof-forces.png`, `full-r2-sdof-math.png`
- `full-r2-damping-critical.png`, `full-r2-damping-overdamped.png`, `full-r2-damping-envelope.png`, `full-r2-damping-undamped.png`, `full-r2-damping-moderate.png`, `full-r2-damping-narrow.png`, `full-r2-damping-dark.png`, `full-r2-damping-light.png`
- `full-r2-workbench-*` for shell-level states: `deck-collapsed`, `deck-expanded`, `inspector-collapsed`, `rail-collapsed`, `rail-expanded`, `parameters-collapsed`, `freeze`, `maximized`, `intermediate`, `mass`, `spring`
- `full-r2-core-2.png` through `full-r2-core-12.png` for the numbered per-workspace core screenshots, plus `full-r2-core-minimum-light.png` for the 900x680 floor at light theme.

When CAD Experience R3 adds new screens or states, extend this convention rather than starting a new one: `<release>-<workspace-or-panel>-<state>.png`, release prefix bumped (e.g. `cad-r3-...`) so old baselines remain a historical record rather than being silently overwritten.

## Full state list to consider per screen

- Theme: dark, light
- Size: 900x680 (`narrow` in the existing convention), 1440x900 (default/no suffix), maximized
- Motion: default, `reduced`
- Selection: none selected, one object selected (mass/spring/damper/DOF/mode), matrix-cell hover (once `mdl-live-mathematics` selection wiring exists for a given module)
- Playback: paused at t=0, mid-playback, frozen/inspect (`freeze` in the existing convention)
- Panel density (CAD R3): Learn, Explore, Inspect
- Panel open/closed (CAD R3): Model Browser expanded/collapsed, Property Manager populated/empty, Equation Dock expanded/collapsed, analysis dock expanded/collapsed

## What each layer should and should not re-check

- **This skill (mdl-visual-qa)**: which of the above combinations matter for the current change, and whether the matrix was actually captured and inspected (not merely generated by a script and left unopened).
- **better-interface**: accessibility, layout, writing, typography, color, and UI-polish findings within whatever states were captured — it does not decide which states to capture.
- **design-review**: an independent 0-4 quality score with Nielsen/WCAG citations on the states it is shown — it does not know MDL's specific workspace list unless told, so hand it the specific screenshots this skill selected rather than asking it to guess the matrix.
- **Project automated tests** (`npm test`, `npm run test:ui`): numerical, interaction, lifecycle, and existing pixel-diff regression — catches drift from a known-good baseline but does not judge whether the baseline itself is good design; that judgment is `better-interface`/`design-review`'s job.
